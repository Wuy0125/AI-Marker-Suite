# 爱多分（eiduo / xuebanyun）主观题阅卷

爱多分教师端和学伴云（xuebanyun.com）是同一套阅卷壳。教师自己登录。脚本不填写账号、密码或验证码，也不内置任何 API 密钥。

本适配器只在主观题阅卷页注入：

- `https://ui.eiduo.com/exam-webapp/marking/index`
- `https://ui.xuebanyun.com/exam-webapp/marking/index`
- 同一路径的其他 `*.eiduo.com` / `*.xuebanyun.com` 子域

登录页 `www.eiduo.com/container/` 和 `www.eiduo.com/container/mobile/` 不匹配。抽查页 `/exam-webapp/marking/check-index` 会当成回评，不显示自动批改按钮。

选择器来自 2026-11-09 的公开前端包（`ui.xuebanyun.com` 的 `exam-webapp` Angular 构建）。下面这份清单需要教师在真实阅卷任务里再核一次。没有教师会话，仓库里无法代替这一步。

## 使用前

1. 用自己的教师账号打开阅卷页，地址应落在上面的 `/exam-webapp/marking/index`。
2. 关闭「批量打分」。批量模式会把一个分数打到多张答题卡上，脚本会拒绝进入。
3. 先用试改模式改 1 到 2 份，再开普通模式。不要一上来无人值守。
4. 题块如果在页面内切换、地址栏的 `examId` / `subjectId` 不变，评分方案不会自动换。换题后看一眼当前方案。

## 现场核对

每一项都在控制台看 `[爱多分]` 日志，并看平台上的实际分数，不要只看脚本提示。

| 步骤 | 期望 |
| --- | --- |
| 打开单份主观题阅卷 | 能检测到分数框和「提交分数」。批量打分开启时不进入 |
| 答题图 | 控制台打印取到的张数，画面是当前这份。加载失败时应暂停，而不是沿用上一份 |
| 满分 | 每个框的满分来自「满分N」。页面上没有满分时，设置里要手填，不能猜 |
| 分步打分 | 有「第N步」时，每一步各有一个分数框，步数和设置里的评分单元一致 |
| 填分 | 框里的数字等于 AI 分数。超过满分或框仍标红时，本次提交中止，需要手改 |
| 不要双交 | 填进分数后的一两秒内，平台不能自己先交卷。只在脚本点击「提交分数」后才交 |
| 0 分 | 填 0 后仍停在当前卷，不能被当成「已经换到下一份」 |
| 下一份 | 提交成功后，答题图路径变化才继续。只是分数框被清空，不能继续 |
| 任务做完 | 出现「是否继续阅下一题」时脚本应停住。不要替教师点「继续」，那是换题不是换人 |
| 回评 | 页头变成「回评模式」，或地址是 `check-index` 时，不自动批改 |
| 换题 | 同一场考试换题块后，确认评分方案仍是这一题的 |

## 已知边界

- 填分要写进页面的 Angular 模型。模型读不到、或和输入框不一致时，脚本放弃本次提交。
- 平台在输入时会自己预约交卷（大约 0.5 到 5 秒，默认 1 秒）。脚本会取消这个预约，再由「提交分数」按钮交卷。若现场看到填分后页面自己跳到下一份，先停用自动批改，把控制台日志留存。
- 换卷只比较答题图 URL 的路径。若两份卷的图片路径完全相同，脚本会等到超时并停下，不会把下一份当成已经换好。
- 仲裁（地址带 `isArbitrate=true`）仍是单份打分，不按回评处理。请先用试改确认仲裁页的按钮文案仍是「提交分数」。
